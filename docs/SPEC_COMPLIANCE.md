# Specification Compliance (v0.1)

Status of each part of the 7-part build specification, with one-line evidence each. Core evidence lives in `core/src/main/kotlin/io/github/wasewasex/nexus/` and `core/src/test/kotlin/io/github/wasewasex/nexus/`.

| # | Specification part | Status | Evidence (one line) |
|---|---|---|---|
| 1 | **Architecture** (two Gradle modules: pure-Kotlin core + Android app) | **Implemented** | `settings.gradle.kts` includes `:core` (no Android deps) and `:app`; all logic lives in `SessionEngine`/`AppState` — one local JSON document, app is a shell that persists and renders it. |
| 2 | **NEXUS-SCOPE implementation** (five-skill profile, selector, five intervention types, budget) | **Implemented** | `engine/Interventions.kt` defines the five types (LISTENING_INPUT, PRODUCTION_FIRST, GRAMMAR_REPAIR, TRANSFER_TASK, PREDICTION_ERROR_REPAIR) with evidence-based costs/cooldowns; `InterventionSelector` + `SkillProfile` + `BudgetController` (0/10/20/30%) verified by `SelectorTest`, `BudgetTest`. |
| 3 | **Real-world experiment mode** (counterbalanced CONTROL/TREATMENT, delayed assessments) | **Implemented** | `experiment/ExperimentManager.assignItems` deterministic counterbalancing + held-out reserve; `SessionEngine.recordReview`/`recordExercise`/`recordAssessment` log per-arm events; DAY7/DAY30 assessments auto-due; verified by `ExperimentTest` and `IsolationTest` (exercises/assessments never touch FSRS). |
| 4 | **Dashboard** (progress, budget, arm aggregates) | **Implemented** | `SessionEngine.studyState()` exposes due/overdue/assessment/budget state and `ExperimentManager.aggregate()` computes per-arm review/exercise/active-seconds and delayed-assessment means from logged events only. |
| 5 | **Privacy and friend testing** | **Partially implemented** | Privacy implemented: zero permissions (no `INTERNET` declared), local-only storage, consent gate (`AppState.learnerConsent`) before anonymized JSON export, deletion = clear app data; friend/multi-learner testing is future (single learner per install in v0.1). |
| 6 | **Development procedure** (build, test, CI) | **Implemented** | `.github/workflows/ci.yml` AnkiDroid-style pipeline: JVM unit tests (`:core:test`, `:app:testDebugUnitTest`) → `assembleDebug assembleRelease` → GitHub Release attach → NEXUS_CI_TOKEN layer check; `JsonRoundTripTest` guards state persistence across releases. |
| 7 | **Scientific integrity** (no hardcoded outcomes, auditable decisions, pre-registration) | **Implemented** | No learning-effect assertions anywhere — tests (`FsrsTest`, `BudgetTest`, `SelectorTest`, `IsolationTest`, `ExperimentTest`, `JsonRoundTripTest`) verify mechanics only; `AuditLog` records every decision incl. skip reasons; DPI computed offline from exports; pre-registered rules fixed in [EXPERIMENT_PROTOCOL.md](EXPERIMENT_PROTOCOL.md); simulation numbers labeled design references, not predictions (README, [LIMITATIONS.md](LIMITATIONS.md)). |
